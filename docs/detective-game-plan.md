# 두 번째 서비스 기획: 데스크톱 추리 어드벤처 (가칭 CASEFILE)

작성일 2026-11-11. 기획 초안이며 코드는 아직 없다. 이름은 가칭이고, 확정되면 `apps/<이름>`과 로비 카드에 반영한다.

## 1. 한 줄 정의

브라우저 안에 "수사관의 컴퓨터 화면"을 그대로 재현하고, 플레이어가 파일·메일·메신저·녹취록을 뒤져 사건의 진상을 스스로 조립하는 텍스트 기반 추리 게임.

참고 감각: Her Story(검색으로 단서 발굴), The Case of the Golden Idol(빈칸 채우기 추리), Orwell(문서 열람과 판단), Hypnospace Outlaw(가짜 OS 안에서 돌아다니기). 이들을 그대로 베끼지 않고, "가짜 데스크톱 + 빈칸 추리"라는 두 축만 가져온다.

## 2. 왜 이 장르가 J-SUN에 맞는가

- Jeenee처럼 텍스트가 중심이라 이미지·3D 자산 없이 글과 UI로 완성도를 낼 수 있다.
- 공통 로그인이 생겼으니 진행 상황을 계정에 저장하고, 여러 기기에서 이어 할 수 있다.
- 사건(케이스) 단위로 콘텐츠를 늘릴 수 있어 서비스가 살아 움직인다. 첫 사건 하나로 출시하고, 이후 사건을 더한다.

## 3. 플레이어 경험 목표

1. "내가 직접 알아냈다"는 감각. 게임이 답을 떠먹이지 않고, 플레이어가 문서를 교차 대조해야 다음 문이 열린다.
2. 가짜 OS의 몰입감. 창을 열고 닫고, 파일을 찾고, 메일 답장을 받는 행위 자체가 재미여야 한다.
3. 한 사건 60~90분. 한 자리에서 끝낼 수 있고, 중간 저장은 자동이다.
{{ 사건에 시간 제한은 두지 않는다. }}

## 4. 핵심 루프

```
자료 열람 → 단서 수집(자동 기록) → 추리판에서 빈칸 채우기 → 검증 → 새 자료 해금 → ...
```

- **자료 열람**: 데스크톱의 앱(파일 탐색기, 메일, 메신저, 음성 녹취록 뷰어, 사내 게시판, 브라우저 흉내)을 돌아다닌다.
- **단서 수집**: 중요한 이름·날짜·물건·장소는 본문에서 자동으로 강조되고, 클릭하면 "단서 보관함"에 들어간다. 플레이어가 메모를 덧붙일 수 있다.
{{ 본문에서 자동으로 강조하지 않는다. 각 단어를 클릭하여 직접 오른쪽 사이드바에 '단서 노트'에 추가하며, 이후 추리판을 작성하면 단서 보관함에 맥락과 함께 자동으로 보관된다. }}
- **추리판**: 사건의 핵심 서술이 빈칸으로 비어 있다. 예) "[ 누가 ]는 [ 언제 ] [ 어디서 ] [ 무엇 ]을 이용해 서버 기록을 지웠다." 보관함의 단서를 빈칸에 끌어다 놓는다.
{{ 보관함이 아닌 '단서 노트'에서 끌어 놓는다. 추리판, 데스크톱 전환이 가능하며 오른쪽 사이드바에는 상시로 단서 노트가 있음. }}
{{ 추리판의 형식을 여러 가지로 둔다. 추리판, 메일전송, 대화 등에 상황에서 빈칸을 채우는 행위가 가능하도록 한다. }}
- **검증**: 빈칸을 다 채우면 "제출"한다. 정답 개수만 알려 주고 어느 칸이 틀렸는지는 알려 주지 않는다(Golden Idol 방식). 1~2개 틀렸을 때만 "거의 다 왔다"고 힌트를 준다.
{{ 1~2개를 틀렸을 때 '단서 노트'에 해당하는 단어가 없는 경우, "아직 찾지 못한 단서가 있는 것 같아."를 출력하며, 단어가 있는 경우, "지금까지 모은 단서들을 잘 살펴봐야해."를 출력한다. }}
- **해금**: 장(chapter) 단위 추리판을 맞히면 다음 자료 묶음이 열린다. 예) 복호화된 폴더, 새로 도착한 메일, 증인의 답장.

- 사건 하나 = 프롤로그 + 3~4장 + 최종 추리판 + 에필로그.

## 7. 콘텐츠 데이터 형식

사건은 코드가 아니라 데이터로 쓴다. 작가가 코드를 건드리지 않고 사건을 추가할 수 있어야 한다.

```yaml
case: missing-night-log
title: 사라진 야간 로그
chapters:
  - id: ch1
    unlocks: [folder:shared, mail:inbox-initial]
    board:
      text: "{who}는 {when} {where}에서 장비를 반출했다."
      answers: { who: suspect.kim, when: time.0213, where: place.server-b }
documents:
  - id: mail-0412
    app: mail
    from: "박지훈 <...>"
    date: 2026-04-12T23:48
    body: |
      ...
    clues: [time.0213, place.server-b]   # 본문에서 강조되고 보관함에 들어갈 단서
clues:
  - id: time.0213
    label: "02:13"
    kind: time
```

- 문서 본문은 마크다운. 단서는 `{{clue:time.0213|02:13}}`처럼 본문 안에 표시한다.
- 빈칸의 정답은 단서 id로만 비교한다. 같은 뜻의 다른 단서는 별칭(alias)으로 처리한다.
- 데이터는 저장소 안 `cases/` 폴더에 두고 빌드 때 검증한다(참조되지 않는 단서, 해금 불가능한 문서를 잡아낸다).

## 8. 진행 저장과 계정

- J-SUN 공통 로그인을 그대로 쓴다. 로그인 없이도 시작할 수 있게 하되, 진행은 브라우저(localStorage)에만 남고 "로그인하면 계정에 저장된다"고 안내한다.
- 저장 단위: 열어 본 문서, 보관함 단서, 메모, 각 추리판의 제출 기록, 메일 답장 선택.
- 표(같은 Postgres, 이 서비스 전용 스키마 `casefile`):
  - `casefile.progress(user_id, case_id, state jsonb, updated_at)` — 사건별 진행 상태 한 덩어리
  - `casefile.submissions(id, user_id, case_id, board_id, answers jsonb, correct_count, submitted_at)` — 추리 제출 기록(통계와 힌트 판단용)
  - `casefile.completions(user_id, case_id, finished_at, play_seconds)` — 완료 기록, 로비 카드에 "사건 1/1 해결" 표시

## 9. 기술 방향 (J-SUN 구조 안에서)

- `apps/casefile`(가칭), Next.js, `basePath: /casefile`, 포트 3002. Caddy와 compose, CI matrix에 한 줄씩 추가.
- 가짜 데스크톱은 클라이언트 컴포넌트. 창 관리(열기·포커스·위치)는 가벼운 상태 저장소 하나로 충분하다. 외부 UI 라이브러리 없이 CSS로 그린다.
- 사건 데이터는 서버에서 읽어 "현재 해금된 범위"만 내려준다. 정답과 미해금 문서는 클라이언트에 절대 보내지 않는다(개발자 도구로 스포일러 방지).
- 추리판 제출은 서버 API에서 채점한다.
- AI는 쓰지 않는다. 추리 게임은 정답이 고정되어야 공정하고, 비용도 0이다. 다만 사건 집필 보조(초안, 교정)에는 써도 된다.

## 10. 화면 톤

- J-SUN 로비와 이어지는 검정 바탕. 가짜 OS는 2000년대 초 업무용 데스크톱 느낌(회색 창 테두리, 고정폭 글꼴 일부)으로 로비와 대비를 준다.
- 효과음 없이 시작. 메일 도착 알림만 작은 소리를 선택 사항으로 둔다.

## 12. 위험과 대응

- **난이도 조절 실패**: 테스트 플레이에서 막히는 지점을 기록하고, 막힌 시간이 10분을 넘으면 그 장에 힌트 단서를 하나 더 넣는다.
- **스포일러 유출**: 정답은 서버에만. 사건 데이터 폴더는 공개 저장소라면 따로 비공개로 둔다.
- **콘텐츠 제작 비용**: 첫 사건은 짧게(3장). 엔진이 안정되면 사건을 늘린다.
- **텍스트 피로**: 문서 하나는 화면 한 장을 넘지 않게. 긴 자료는 녹취록 앱처럼 검색 가능한 형식으로.
